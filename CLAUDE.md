# Claude Code — project context

## Структура

- Гра існує в **одній версії** — репозиторій GitHub `MykolaHavrilov/RPG-game_v2`, локальна версія — `H:\Game_NEW\game`
  (звичайна тека, **не git-клон** і не пов'язана з GitHub).
  Та сама папка працює на Windows, Android, планшетах і телефонах.
- Запуск: GitHub Pages (PWA, встановлюється як застосунок у Chrome/Edge на ПК і на Android),
  або локально подвійним кліком по `index.html` (тоді без офлайн-кешу, `pwa.js` нічого не робить).
- Адаптація під екрани — тільки через CSS (`@media (max-width: 700px)`, `@media (hover: none)`),
  без окремих файлів чи гілок під платформи.
- Стара двоплатформна версія лежить у `H:\Game_NEW\вихідні данні` лише як архів — її не змінювати.

## Правила оновлень

- Картинки — тільки `.webp` (розширення задані в `data/classes.js`, `data/items.js`, `data/enemies.js`).
- Якщо змінюються/додаються файли, що кешує `sw.js`, — оновити список `PRECACHE`
  і підняти номер `CACHE` (`rpg-game-vN` → `vN+1`), інакше гравці отримають старий кеш.
- Усі скрипти — звичайні (не ES-модулі), щоб гра відкривалась і з `file://`.
- У папку гри кладуться лише ресурси, які гра використовує; невикористане — у `_old` (не йде в git).
- Версії — через git-коміти (з тегами `v0.N` для помітних етапів), а не копії папок.

## GitHub (обов'язково)

- Локальна тека `H:\Game_NEW\game` — окрема локальна версія. Не робити її git-клоном,
  не запускати в ній git-команд і не синхронізувати автоматично з GitHub.
- **Якщо є доступ до ПК** (тека `H:\Game_NEW` підключена до сесії) — зміни спершу вносити ЛИШЕ на ПК,
  в `H:\Game_NEW\game`; на GitHub — тільки після підтвердження користувача.
  Перед зміною файлів на ПК — бекап у `H:\Game_NEW\backup\` (правило бекапів нижче).
- Якщо ПК недоступний — зміни можна вносити одразу в GitHub (після «так» користувача),
  а локальну теку оновити, щойно ПК з'явиться на зв'язку: звірити з GitHub, бекап, потім файли.
- **Перед кожним `git push` питати користувача**, чи відправляти зміни на GitHub зараз.
  Він спершу перевіряє локальну версію, чи відповідає задуму. Без його «так» — не пушити.
  Пуш робити з окремого клону репозиторію (не з локальної теки), переносячи туди лише підтверджені файли.
- Перед пушем звірити ці файли: якщо на GitHub вони змінились з іншого пристрою — зупинитись і узгодити з користувачем.
- Якщо правки вносились напряму в GitHub (наприклад, з телефону) — окремо звірити локальну теку
  з репозиторієм, показати користувачу різницю і лише після його згоди скоригувати локальну теку.

## Бекапи (обов'язково)

- Якщо одне оновлення містить **більше 100 правок** (змінених рядків за `git diff --shortstat`:
  додані + видалені), після нього зробити архів гри `backup_v.NNN.zip`
  і покласти в `H:\Game_NEW\backup\`.
- `NNN` — поточна версія, три цифри: попередній номер +1 (`backup_v.001.zip`, `backup_v.002.zip`, …).
  Останній номер дивитись у списку файлів `H:\Game_NEW\backup\`.
- В архів іде вміст гри (усі файли репозиторію без `.git`) у стані після оновлення.
- Старі архіви не видаляти й не перезаписувати.
